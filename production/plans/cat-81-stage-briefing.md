# 고양이 81 — 스테이지 안내 토스트 (2026-09-25)

> 근거: 아기(75)·배관(79)·문지기(80)처럼 스테이지마다 달라지는 게 늘었는데 화면에 알려 주는 게 없다. 킁킁(R)도 발견하기 어렵다.

## 규칙
- 벽 속 맵이 다 지어지면 전원 화면 우상단 토스트(6초):
  - "스테이지 n/N — 식량 Q 모아 목적지(주황 방)로" (강조)
  - 문지기 있으면 "문지기 고양이가 목적지 앞을 지켜요 — 털실·레이저로 끌어내기" (경고)
  - 아기 있으면 "아기 고양이 — 들키면 냐앙! 엄마가 달려와요" (경고)
  - 스테이지 1이고 배관 고리가 있으면 "회색 배관은 쥐만 지나가요 · R 킁킁 = 목적지 냄새" (보조)
- 토스트 최대 3개라 한 번에 3줄까지(스테이지 1엔 문지기·아기가 없어서 겹치지 않음).

## 구현
- `GridZoneBuilder.StageBriefingClientRpc` → `EventBus.StageBriefing` → `UI/ToastWidget`(Show에 시간 인자 추가). docs/03 RPC 줄, docs/12 표.

## 확인 (계획)
- 1인: 스테이지 1·3 로드 → 토스트 문구·색. 2인: 클라 로그 "스테이지 안내 연출".

## 진행 — 구현·확인 (2026-09-25)
- `EventBus.StageBriefing`, `GridZoneBuilder.SendBriefing/StageBriefingClientRpc`(플래그 상수 BriefKitten·BriefGuard·BriefPipe), `ToastWidget.OnStageBriefing` + `Show(text, stripe, seconds)`, `StageQuota.QuotaFor/StagesTotal`.
- 고친 것: 에디터에서 Stage_Walls를 바로 켜면 빌더가 StageQuota보다 먼저 스폰돼 "1/1 식량 0"이 나감 → NV 대신 밸런스에서 바로 읽음.

| 확인 | 결과 |
|---|---|
| 스테이지 1 | "1/5 식량 150 특징 4(배관)" |
| 스테이지 3 화면 | 우상단 토스트 2개: "스테이지 3/5 — 식량 300 모아 목적지(주황 방)로"(강조), "문지기 고양이가 목적지 앞을 지켜요 — 털실·레이저로 끌어내기"(경고, 두 줄로 감김) |
| 2인 | 스테이지 5 — 호스트·클라 둘 다 "5/5 식량 450 특징 7(아기·문지기·배관)", 예외 0 |

- 참고: 클라 첫 실행이 접속 5번 다 실패한 적 있음(호스트 로그엔 이탈만) → 다시 켜니 바로 접속. 진행 중(InRun) 참가 거절은 사양(docs/03).
