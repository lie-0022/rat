# 고양이 40 — 문 닫기·문 밀기 + 쥐 전용 틈 (2026-09-24, design/cat-ideas/09 "문을 밀고")

## 목표
쥐가 **문을 닫고** 도망치면 고양이는 문 앞에서 **4초 동안 몸통으로 밀어야** 연다 — 도망 시간. 진짜 안전은 **쥐만 지나는 틈**(벽 구멍 0.8m 폭·1.4m 높이 — 고양이 에이전트 폭 1.1·키 1.7은 못 지나감). 순찰 중인 고양이는 닫힌 문을 밀지 않는다(문을 열고 다니는 고양이는 너무 세다).

## 설계
- 데모 레이아웃 **창고방**(남동쪽 모서리 x 13~20, z -20~-14): 서쪽 벽에 문(폭 1.8m), 북쪽 벽에 쥐 구멍(폭 0.8·높이 1.4, 위는 인방). 벽은 RoomStatic(시야 차단). 안에 치즈 1개.
- `World/RoomDoor` (NetworkBehaviour, IInteractable 0.4s "문 닫기"/"문 열기"): `Open` NV(기본 열림) → 경첩 판 90° 회전(모든 클라). 닫히면 판의 `NavMeshObstacle`(carve) 켜짐 → 고양이 경로가 막힌다. 쥐가 닫으면 소리 25(Impact, 귀속). 고양이가 1m 안이면 못 닫음.
- 밀기(호스트, 0.25s마다): 닫힌 문 1.4m 안에 **Chase·Suspicious·Track·Search** 고양이가 있으면 밀기 누적, 없으면 0으로. 누적 ≥ `doorPushSeconds` 4 → 열림. `PushProgress` NV(0~1) → 판이 덜컹덜컹(클라 연출).
- 문 판은 NavMesh 베이크에서 제외(`NavMeshModifier.ignoreFromBuild`) — 열림·닫힘은 런타임 carve로만.
- 수치: doorPushSeconds 4 · doorPushRange 1.4 · doorCloseNoise 25.

## 검증
- 닫힌 문: 밖 → 안 경로 Partial, 열린 문: Complete. 쥐 구멍: 고양이 경로 없음(닫힌 문일 때 Partial 유지).
- 쥐가 안에 숨고 문 닫음 → 고양이 조사(Suspicious)로 문 앞 → 약 4s 밀기 → 열림 → 들어감.
- Patrol 고양이는 문 앞을 지나도 밀기 누적 없음.
- 쥐가 닫을 때 소리 25(귀속). 2인: 클라 Open 복제·덜컹 연출 로그.

## 검증 결과 (2026-09-24)
- 레이아웃 고침 2번: ① 문틈 1.4m는 고양이 반경을 빼면 길이 0.3m라 NavMesh가 끊김 → 1.8m. ② 인방(아래 2.1m)이 NavMesh 에이전트 높이 2.0에 걸림 → 인방 제거. 문 오브젝트를 서쪽으로 돌린 뒤 로컬 축 교정.
- NavMesh: 문틈 있음, 쥐 구멍 없음. 열린 문 경로 Complete, 닫힌 문(carve) Partial.
- **설계 보강 2개**: ① 닫힌 방 안이 목적지면 NavMesh가 북쪽 벽 바깥으로 보내 문을 밀 일이 없었다 → `RoomDoor.Redirect`로 문 앞으로. ② 미는 4s 동안 의심 게이지가 식거나(3s) 추격 놓침(3s)으로 포기 → `ServerHoldAtDoor`.
- 추격 시나리오: 고양이 Chase 0.9s → 쥐가 창고방으로 들어가 문 닫음 → 고양이 0.7s 뒤 문 앞 → **3.9s 밀어 열림**(계속 Chase) → 0.7s 뒤 방 안.
- 순찰 고양이를 닫힌 문 0.7m 앞에 6s 세워 둠 → 밀기 0, 닫힌 채.
- 쥐 캡슐(반경 0.3·키 1.2)이 쥐 구멍 자리에 겹침 없음, 대조(벽 자리) 겹침 있음.
- 2인: 빌드 클라 "문 연출: 닫힘 → 덜컹덜컹 → 열림"(4.7s), 예외 0.
- 첫 시도들 무효: 쥐가 스폰 자리에서 계속 잡혀 고양이가 Patrol이 안 됨(쥐를 먼저 멀리), RaiseGaugeTo는 "새 자극"이 아니라 순찰 고양이를 의심으로 안 바꿈 → 실제 추격 시나리오로.
- 미검증: 실제 E 홀드로 닫기, 쥐가 쥐 구멍을 실제 입력으로 통과.
