# 코드 작업 뒤 검증하지 않기

사용자 지시 (2026-10-05): **"앞으로 코드 작업 후에 검증하지 않도록 — 엄격히 준수해."**

## 하지 않는 것 (코드를 고친 뒤)

- 유니티 컴파일 확인 (`refresh_unity`, 콘솔 오류 읽기로 확인하기)
- EditMode·PlayMode 테스트 실행 (`run_tests`, Test Runner)
- 플레이 시험 (`Tools/RatGame/Test/...`, Run All Quick·Full·Everything, 통째 시험·소크)
- 개발·릴리스 빌드, 빌드 클라 띄우기, 릴리스 연기 시험(`-smokehost`)
- 성능 측정(`-perflog`), 시드 스트레스, 스크린샷으로 확인하기
- "확인해 보니 통과" 같은 검증 결과 보고 — 하지 않았으니 쓰지 않는다

## 하는 것

- 고치고 → (요청이 있으면) 커밋 → 무엇을 바꿨는지 짧게 보고.
- 보고에는 "검증은 안 했다"를 한 줄로 밝힌다(사실대로 — 통과했다고 쓰지 않는다).
- 사용자가 직접 할 확인 방법(CLAUDE.md "작업 산출 형식"의 테스트 방법)은 글로 적어 줄 수 있다 — 실행은 하지 않는다.
- 커밋 전 정리(`git checkout -- "Assets/_Project/Art/Fonts/Jua/Jua SDF.asset"` 등 작업 흔적 되돌리기)는 검증이 아니므로 계속 한다.

## 예외

- 사용자가 **그 작업에서** 명시적으로 "검증해", "테스트 돌려", "빌드해", "플레이해 봐"라고 하면 그것만 한다.
- 한 번 허락은 그 요청 한 번에만 — 다음 작업엔 다시 검증하지 않는다.

## 이전 방식과 충돌할 때

이 스킬이 우선한다. 메모리 `rat-work-style`("직접 검증 후 체크받기"), `production/loop-state.md`·docs/14의 "검증 포함" 문구, CLAUDE.md "넷코드 수정 시 MPPM 테스트 방법 제시"는 **방법을 글로 적는 것**까지만 — 실행하지 않는다.
