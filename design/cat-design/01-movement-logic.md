# 01 — 움직이는 로직

축은 여섯 개다. 축마다 후보를 나란히 두고, 각 후보에 **어떻게 움직이나 / 쥐에게 어떻게 보이나 / 장점 / 단점 / 구현 크기**를 적는다.

---

## 1. 순찰 모델 — "아무 일 없을 때 고양이는 뭘 하나"

지금: 웨이포인트 배열을 순서대로, 도착하면 2~5s 대기. 예측 가능하고 밋밋하다.

### A. 고정 루프 (현재)
- 방의 `CatWaypoint` 2~4개를 순서대로 순회.
- 보임: 규칙적. 두 바퀴 보면 외운다.
- 장점: 구현 0, 디버그 쉬움, 레벨 디자이너가 완전히 통제.
- 단점: 학습되면 긴장 0. 방이 여러 개면 방 간 이동이 없다(현재 코드는 씬 전체 웨이포인트를 한 배열로).
- 크기: 있음.

### B. 스팟 그래프 확률 이동
- 방 안 **스팟**(잠자리·밥·창가·모서리·통로 입구)에 타입과 가중치. 도착하면 스팟의 **행동**(앉기 10s, 그루밍, 창 보기)을 하고, 다음 스팟은 인접 그래프에서 가중치 랜덤(같은 스팟 연속 금지, 최근 3개 회피).
- 보임: 고양이가 "볼일 보러" 다니는 느낌. 어디로 갈지 대략은 알지만 정확히는 모름.
- 장점: 규칙성과 랜덤의 중간. 스팟 타입이 텔레그래프(밥그릇 앞이면 곧 밥). 방 모듈 규약에 스팟만 넣으면 됨. 02 맵핑의 스팟 카탈로그와 직결.
- 단점: 스팟 데이터가 방마다 필요. 가중치 튜닝.
- 크기: 중 (SO 하나 + 그래프 선택 30줄 + 행동 타이머).

### C. 영역(Territory) 기반
- 고양이마다 **영역**(방 1~2개)이 있고 그 안을 랜덤 지점 배회(`RandomPointAround`처럼) + 영역 경계 순찰. 영역 밖은 추격 때만.
- 보임: "이 방은 저 고양이 구역". 영역 밖은 안전.
- 장점: 맵 지식이 곧 실력. 2마리면 영역이 갈려 자연스러운 역할 분담. 데이터가 거의 없음(영역 볼륨 하나).
- 단점: 랜덤 배회는 멍청해 보일 수 있음(벽 보고 서 있기). 영역 밖이 완전 안전이면 긴장 감소 → 가끔 "순찰 나가기" 필요.
- 크기: 소 (볼륨 + 랜덤 샘플).

### D. 시간표(루틴)
- `cat-ideas/02`. 밥·햇볕·화장실·그루밍 슬롯을 순서대로, 각 슬롯 20~40s, 다음 슬롯 8s 전 예고음.
- 보임: 예측 가능한 리듬 + 예고. "지금은 햇볕 시간, 부엌 비었다."
- 장점: 필러 2에 가장 충실(소리로 상태 읽기). 방 모듈이 스팟 태그를 제공하면 자동.
- 단점: 너무 읽히면 쉬움 → 랜덤 오프셋·자극 중단·디렉터 조절 필요. 스팟이 없는 방에서 폴백 필요.
- 크기: 중 (B 위에 슬롯 스케줄러).

### E. 관심 주도 자유 이동
- 순찰 목적지가 없다. 매 순간 **가장 흥미로운 것**(움직이는 물건·소리·냄새·스팟 매력도)을 향해 간다. `cat-ideas/13`의 관심 점수를 순찰에까지 확장.
- 보임: 살아 있는 동물. 예측 불가.
- 장점: 창발. 쥐의 모든 행동이 고양이를 움직인다.
- 단점: 예측 불가 = 불공평하게 느껴질 수 있음. 튜닝 지옥. 그레이박스에서 "왜 저기 갔지?"를 설명하기 어려움.
- 크기: 대.

### F. 하이브리드 (추천 후보)
- 뼈대는 **B 스팟 그래프**, 스팟 행동 중 일부가 **D 루틴 슬롯**(밥·햇볕은 시간표, 나머지 스팟은 확률), 자극이 오면 기존 FSM(의심/추격)이 끼어들고, 관심(E)은 순찰 중에만 낮은 우선순위로.
- 이유: 레벨 디자이너 통제(스팟 배치) + 예고 가능한 리듬(루틴) + 약간의 창발(관심). 각각 따로 켜고 끌 수 있어 데모 범위 조절이 쉽다.

| | A 루프 | B 그래프 | C 영역 | D 루틴 | E 관심 | F 하이브리드 |
|---|---|---|---|---|---|---|
| 읽힘(필러2) | ◎ 너무 | ○ | ○ | ◎ | △ | ○ |
| 긴장 | △ | ○ | ○ | ○ | ◎ | ○ |
| 디자이너 통제 | ◎ | ○ | ○ | ○ | △ | ○ |
| 데이터 | 웨이포인트 | 스팟 SO | 볼륨 | 스팟+슬롯 | 자극 시스템 | 스팟+슬롯 |
| 크기 | 0 | 중 | 소 | 중 | 대 | 중+ |

## 2. 감각 모델 — "고양이는 무엇으로 쥐를 아나"

지금: 의심 게이지 하나(0~100). 시야 목격 시간 × 60/s × 거리보정, 소음 × 0.8. 30에 의심, 100 또는 직접목격 1s·2m 이내에 추격.

### A. 단일 게이지 (현재)
- 장점: 단순, HUD 하나로 읽힘("?"+게이지).
- 단점: 소리와 시야가 같은 통에 섞여 "왜 의심하지?"가 흐림. 유인(관심)과 의심이 같은 상태를 다투면 우선순위가 꼬인다(지금은 Chase 아래로 하드코딩).

### B. 이축 — 의심(위험) vs 관심(흥미)
- 의심: 플레이어 목격·Break/Trap 소음 → 추격으로 간다. 관심: 굴러가는 물건·유인 아이템·스팟 매력 → 구경하러 간다. **의심이 임계 이상이면 관심 무시.**
- 보임: 귀 방향(관심) vs 꼬리·자세(의심)로 다르게 읽힌다. HUD "?"는 의심만.
- 장점: "고양이가 놀고 있을 때만 유인이 먹힌다"가 규칙으로 명확. 13 관심 생태계와 03 호기심의 밑바탕.
- 단점: 읽어야 할 축이 둘. 표현 없으면 혼란.
- 크기: 중.

### C. 확신 + 위치 추정 (인식 모델)
- 게이지 대신 **"쥐가 있다는 확신 0~1"과 "어디쯤인지 추정 위치(불확실 반경)"**. 시야는 확신↑·반경↓, 소음은 확신 조금↑·반경은 소음 지점 중심으로. 확신이 높고 반경이 작으면 추격, 확신은 있는데 반경이 크면 수색(반경 안 스팟 순회).
- 보임: 고양이가 "대충 저쪽"을 알고 두리번거리다 좁혀 오는 느낌 — 훨씬 동물답다.
- 장점: 수색(14)이 자연스럽게 나온다. 마지막 목격점 하나가 아니라 "지역"을 뒤진다. 웅크림·어둠이 반경을 키우는 식으로 은신 수단이 통일된다.
- 단점: 튜닝 어려움. HUD 표현(게이지 하나로 접어야 함: 확신×(1-반경/최대)).
- 크기: 중~대.

### D. 감각 확장 — 움직임·냄새
- 축이 아니라 입력 추가: 움직임 감지(속도 ≥1.5의 Carryable → 관심), 냄새 자국(Edible 든 쥐 → 추적). A/B/C 어디에나 얹는다(`cat-ideas/03·06`).
- 주의: 입력이 늘수록 쥐가 지켜야 할 규칙이 는다 → 데모는 시야+청각+움직임까지, 냄새는 나중.

**추천**: B(이축)로 가되, 의심 축 내부에 C의 "추정 위치 반경"만 빌려 온다(확신 대신 게이지 유지 — HUD 호환). 즉 게이지 + 추정 반경 + 관심 축.

## 3. 추격·추적 모델 — "들킨 다음"

지금: 시야 있으면 타깃 위치로 직행, 시야 잃으면 마지막 목격점으로 3s → Suspicious → 6s 배회 → 복귀.

### A. 직선 추격 + 마지막 목격점 (현재)
- 단순, 월핵 없음. 직선 도망이 통한다(밸런스 축). 단점: 문 뒤로 가면 3초 뒤 포기 — 너무 관대하고 밋밋.

### B. 예측 추격 (Lead)
- 타깃 속도로 1~1.5s 뒤 위치를 예측해 그 지점으로 간다(`NavMesh.SamplePosition`). 시야 잃으면 **마지막 속도 방향으로 3m 더** 가 본다.
- 보임: 코너를 돌면 고양이가 "따라 도는" 느낌. 직선 도망은 여전히 됨(속도 차).
- 장점: 저렴하고 훨씬 무섭다. 단점: 예측이 벽을 뚫으면 이상 → 샘플 실패 시 A로 폴백.
- 크기: 소.

### C. 차단(Cut-off)
- 타깃과 쥐구멍/문 사이 **경로상의 초크포인트**를 계산해 그리로 먼저 간다(두 마리면 한 마리가 차단 — `cat-ideas/07` 협공).
- 보임: 도망가는 길목에 고양이가 먼저 와 있다.
- 장점: 협동 압박(길을 바꾸게 함). 단점: 정확하면 도망 불가 → "그럴듯하게만"(확률 40%, 예측 2s까지). 초크포인트 데이터 필요(02 맵핑 통로 태그).
- 크기: 중.

### D. 수색 (Search)
- 시야 상실 후 A처럼 포기하지 않고 **추정 반경(감각 C)** 안 숨을 곳·스팟을 25s 순회하며 킁킁. `cat-ideas/14`.
- 보임: 숨어 있으면 코앞까지 온다. 장점: 추격의 결말이 다양해짐. 단점: 숨을 곳이 맵에 있어야 의미.
- 크기: 중.

### E. 추격 체력
- 고양이도 **달리기 체력**(10s)이 있고 다 떨어지면 걷기(3.0)로 20s. 쥐 스태미나(sprint 20/s)와 맞물려 **누가 먼저 지치나** 게임.
- 보임: 헐떡이는 고양이. 장점: 추격에 결말 리듬, 댕청함(필러 4). 단점: 너무 자주 포기하면 안 무섭다 → 체력은 길게(12s), 회복은 느리게.
- 크기: 소.

**추천**: B(예측) + E(체력)를 기본으로, D(수색)는 숨을 곳이 맵에 들어갈 때 함께. C는 2마리 이후.

## 4. 이동 실행 — "실제로 어떻게 옮기나"

### A. NavMeshAgent 직접 (현재)
- 장점: 안정, 회피·경로 공짜. 단점: 미끄러짐·회전 느낌이 로봇 같음. 점프 없음(선반 불가).

### B. NavMeshAgent + NavMeshLink(점프)
- 선반·소파 위 층을 별도 NavMesh 영역으로, Link로 점프. Link 통과 중엔 Agent를 끄고 **포물선 보간 0.5s** + 착지 소음 20.
- 장점: 수직 순찰(`cat-ideas/09`), 고양이다움. 단점: 런타임 베이크와 Link 호환 확인, 착지 실패 개그(11)를 넣으려면 보간 제어 필요.
- 크기: 중.

### C. Agent 경로 + 물리 몸통
- 경로는 Agent가 구하고 몸은 Rigidbody가 따라감(쥐와 같은 방식). 미끄러짐·밀림·룸바 충돌이 자연스럽다.
- 장점: 필러 1과 통일(고양이도 물리에 당함 — 비누 미끄러짐이 공짜). 단점: 튜닝 어렵고 NavMesh 이탈 복구 필요, 네트워크는 NetworkTransform이라 그대로.
- 크기: 중~대.

### D. 스플라인 루트 + 국소 회피
- 디자이너가 그린 스플라인을 따라 순찰, 장애물만 회피. 절차 조합 맵(docs/10)과 상성이 나쁨(방마다 스플라인).
- 비추.

**추천**: A 유지 + B(Link)는 맵에 선반 층이 생길 때. C는 미끄러짐 하나만 "Agent 끄고 3m 슬라이드 → Warp" 특수 처리로 흉내(전면 물리화는 안 함).

## 6. 속도·체력·난이도 손잡이

### 속도 관계 (밸런스 축 — 유지)
- 쥐 걷기 3.8 / 달리기 6 / 웅크림 1.9. 고양이 순찰 2 / 의심 3 / 추격 5.5 / 유인 4.
- 새 규칙 제안: **추격 5.5는 "직선 최고 속도"**, 코너·문턱에서 감속(회전 반경) → 쥐의 지그재그가 실제로 도움되게. `NavMeshAgent.angularSpeed 360→240`, `acceleration 12→8` 실험.

### 고양이 체력 (3-E)
- `CatSprintSeconds 12`, `CatTiredSpeed 3.0`, `CatTiredSeconds 20`, `CatSprintRecoverPerSec 1`.

### 난이도 손잡이 — 디렉터(12)나 설정이 돌릴 수 있는 것만
